# 首页养成表现：同类产品与实现方案

调研日期：2026-10-04。针对用户对多次兔子握壶调整仍不自然的反馈，重新选择表现形式。本文记录调研和设计建议；后续已按推荐方向实现 SVG 小花园，见 [实现与验收说明](garden-svg-scene.md)。

## 结论

推荐改成 **“一座慢慢长大的小花园”**：以一株有简单表情的植物为视觉中心，水滴直接滋养土地；长叶、开花、结果以及蝴蝶、小鸟的到来构成长期变化。保留学习、水滴、每日额度、12 滴里程碑、礼物、成长日历这套闭环。

此前投入太多精力修补兔子手臂和握壶位置。部件对齐、动画正常运行，并不能证明角色的姿态自然。下一版应先确定完整的静态造型和成长前后关系，再加入少量有因果联系的动作。

这是一项结合案例与当前项目的设计判断，不是上述产品共同采用某种技术的事实。商业产品的具体动画引擎未公开核实；下文仅对确实读过的开源代码描述实现。

## 值得借鉴的产品

| 参考 | 官方能确认的做法 | 对本项目的启发 |

补充资料：Kinder World 的[官方资料页](https://www.playkinderworld.com/press-kit)介绍了程序生成植物；Habitica 的[宠物文案](https://github.com/HabitRPG/habitica/blob/develop/website/common/locales/en/pets.json)和[官方图像仓库](https://github.com/HabitRPG/habitica-images)可用于核对上述机制。没有验证这些商业产品的完整操作流程，也没有据此声称它们使用 GSAP、Rive 或其他特定引擎。

## 实际读过的实现

### Pomodoro Garden：最贴近当前原生前端的参考

[仓库](https://github.com/snowhiteohno/pomodoro-garden) · [在线示例](https://pomodoro-garden-theta.vercel.app/) · [植物生成源码](https://github.com/snowhiteohno/pomodoro-garden/blob/main/src/garden.js) · [动画样式](https://github.com/snowhiteohno/pomodoro-garden/blob/main/style.css)

这是一个小型开源示例，适合阅读机制，不作为成熟生产框架背书。检查了植物生成源码与 CSS，并打开了在线界面；未完成长时间的专注流程与持久化验收。

- 监听完成事件，只有专注完成才调用 `plantSeed()`；动画层接收结果，不决定任务是否完成。
- 使用原生 JavaScript 生成八类 SVG 植物。保存类型、随机种子、位置和大小，重绘时用相同种子恢复相同形状。
- SVG 统一根部坐标，画面位置与植物内部结构分开控制。
- 出场主要通过从底部缩放、淡入，以及 SVG 线条逐渐显现实现，没有动物骨骼或拿取道具动作。

值得借鉴的是事件与绘制分离、固定根部、稳定造型和轻量的生长反馈。其随机花园布局与外观并不直接满足我们的 16 阶段，应重新设计。本项目也不应照搬它的本地存储替代服务端账本。

该项目[许可为 MIT](https://github.com/snowhiteohno/pomodoro-garden/blob/main/LICENSE)。若实际借用代码，需要保留许可声明；当前只作研究。

### Rive：有可参考的植物交互案例，但仍需制作源动画

[Interactive Plant with Wind Effects](https://rive.app/community/files/21035-39547-interactive-plant-with-wind-effects-bones-and-state-machine/) 的作者说明使用骨骼和状态机，让植物响应左右方向的风；页面标注 CC BY。这说明植物柔和弯曲可以通过专业动画工具完成。

该案例是风吹交互，不是现成的 16 阶段养成系统。本次只核查了作者页面，未下载或集成 `.riv`。要采用 Rive，仍需设计植物、制作各阶段与状态切换，并维护可编辑源文件；装上播放器不会自动把现有拼接素材变自然。

Habitica 的代码与图像采用不同许可，见[许可文件](https://github.com/HabitRPG/habitica/blob/develop/LICENSE)：代码 GPLv3，部分原创资源 CC BY-NC-SA 3.0。这里只借鉴产品机制，不计划复制其角色素材。

## 三种可落地方向

| 方向 | 画面与动作 | 适合程度 |
| --- | --- | --- |
| **小花园中的植物主角（推荐）** | 整体造型圆润、叶片少而清楚；水落到土里，植物舒展；升级长出新器官，后期出现花果与访客 | 与当前 16 阶段文案和水滴含义最吻合；既有即时陪伴，也有长期变化 |
| 微型岛屿 / 生态瓶 | 每次照顾有雨滴与涟漪；里程碑逐步增加花丛、景物和小生命 | 更适合强调建设和收藏，但需重新对应阶段文案，避免让新景物误被理解为新的兑换系统 |
| 种子精灵 / 宠物蛋 | 获得滋养时轻轻弹起、眨眼；阶段升级改变整体轮廓或形态 | 陪伴感强，但需要额外世界观和成套角色设计，当前不优先 |

推荐方向的具体表现如下。时间只是下一轮打样的起点，不是已经实现或测量的结果。

1. **静止时**：中央植物与土地是一个完整构图，根部固定；主要依靠造型、表情和少量叶片轻动表达生命力。
2. **普通照顾，约 1.2–1.8 秒**：水滴落到根部，土地出现短暂涟漪，植物轻轻抬头或舒展，随后安静。水滴结束位置与根部共用场景坐标。
3. **12 滴成长，约 2–3 秒**：保留旧的主体，新叶从枝节展开、花苞张开或果实出现；成长变化完成后再展示礼物。
4. **长期变化**：从幼苗到茂盛、花果，再到蝴蝶和小鸟来访。此前获得的主要景物留下，成年后嫩叶—花苞—花—果的循环表现为季节更新，不让整片花园突然清空。
5. **美术**：奶油底色、柔和配色与纸感可以沿用，主体改为轮廓清楚、结构一致的原创插画。先画一套完整造型，不继续拼独立生成的肢体。

## 与现有养成系统的对应

当前规则见 `public/garden.js` 中的 `summarize()`、`stageAt()` 及服务端花园逻辑。以下属于必须保持的业务约束：

| 现有系统 | 新表现 |
| --- | --- |
| 完成一组获得水滴，每天最多获得 3 滴 | 原样保留 |
| 当天完成过学习组、有余额，每天最多浇水 3 次 | 点击照顾后，消耗与限额逻辑原样保留 |
| 累计每 12 次照顾触发里程碑 | 从同一累计值计算新叶、花果等变化，不新建一套经验值 |
| 16 个展示阶段，后期循环 12–15 | 推荐方案可以逐项对应原有树苗、侧枝、花果与访客文案 |
| 成长礼物与日历记录 | 继续读取原记录，展示与场景一致的阶段结果 |
| 服务端保存、请求幂等、失败重试 | 保持；动画只表现已确认结果 |

仅更换视觉层不需要迁移历史学习数据。若选择岛屿或宠物形式，必须同步更换首页、礼物、日历中的阶段名称，但仍以原累计值映射，不能擅自更改兑换成本或新增成长资源。

## 技术建议与下一轮验收重点

推荐使用 **统一 SVG 场景 + 已接入的 GSAP**。SVG 负责可编辑的完整植物、叶片和花果结构，GSAP 编排水滴、叶片舒展与阶段变化。现有场景控制器的生命周期和业务接入可复用；兔子握壶的素材与运动逻辑不继续扩展。

先打样三个片段：幼苗的普通照顾、第一片新叶展开、成年植物开花。把静态构图和动作连起来检查，在手机与桌面都能清楚看见同一株植物发生变化后，再扩展全部阶段。代码测试只能保证状态与流程，不能代替这一步视觉检查。

验收聚焦：根部稳定、枝叶连接连续、动作幅度克制、普通照顾与升级有区分、每个里程碑确实增加可辨认的变化，以及第 3 次照顾仍完整播完。保留减少动态效果、资源失败、切走页面与后台完成等处理。

如果后续需要更细的植物弯曲或丰富表情，可以再把同一视觉接口替换为 Rive；当前没有必要仅为“专业动画库”更换技术栈。
