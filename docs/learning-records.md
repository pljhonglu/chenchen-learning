# 统一反馈与练习记录

这次调整统一各学科的确认选项，把全科练习历史集中到首页的「练习记录」，并保留可核对的原始活动。统计展示本次完成表现和已有的跨天证据，不把一次点读、描写或选择题结果换算成精确的“熟练度分数”。复习排期仍使用原有固定间隔，没有接入 FSRS。

## 一套确认选项

| 保存结果 | 页面选项 | 含义 |
| --- | --- | --- |
| `independent` | ✓ 自己完成 | 这次检查中没有依赖提示完成 |
| `supported` | ◐ 提示后完成 | 需要提示或帮助才能完成 |
| `again` | ↻ 还要练习 | 当前还需要继续练习 |
| `practice` | 已练习 | 只记录参与，没有有效确认 |

需要人工观察时，三个选项的顺序、文字和样式一致。程序能够判断的题目直接记录结果，不再多加一组让家长重复评分的按钮。

| 内容 | 确认对象 | 确认来源 | 统计边界 |
| --- | --- | --- | --- |
| 古诗 | 背诵 | 家长确认 `parent` | 页面播放过范读，会记录本次接触示范；这次表现不算延迟独立回忆 |
| 英语 | 听音辨认 | 程序判断 `automatic` | 保留首次选图、提示和示范信息；跟说只记录参与，不认定发音正确 |
| 汉字 | 书写 | 家长确认 `parent` | 描写与纸写分别记录练习方式；不能由描完推断认字、笔顺正确或独立书写掌握 |
| 拼音 | 拼音认读 | 家长确认 `parent` | 按具体音保存；读过或听过本身不等于独立认读 |
| 数学、分解组合 | 解题 | 程序判断 `automatic` | 依据本组五题的作答记录；保留正确题数和题目数 |

汉字、拼音本轮练习后的确认带 `afterPractice` 标记。本次“自己完成”仍可显示，但与隔天未经示范的独立回忆分开。程序无法观测线下是否额外练习，跨天间隔只描述已记录活动之间的距离。

## 一个全科记录入口

首页的「练习记录」是统一入口，英语的每个词条不再各放记录按钮。记录页只读，不会创建活动，也不会更改下次复习日期。

- 日期可选今天、昨天、近 7 天或指定的历史日期。
- 每天再按古诗、英语、汉字、拼音、数学、分解组合汇总，直接列出练过的内容。英语同一天的词汇一起展示。
- 展示所选范围的学习天数、不同内容数、独立完成次数与有效确认次数。
- 七天趋势展示截至所选日期的连续七天，每天练过多少项不同内容。切换单日记录不会把之前六天清零。
- 各学科分别展示确认结果，注明程序判断或家长确认。不同能力不混成一个“会了”的标签。
- 历史较少或没有新格式确认时显示“暂无确认”，不推算百分比分数。空日期正常显示没有记录。

“独立 4 / 5 次”是五次有效确认中四次独立完成。它没有承诺孩子现在能记住 80% 的内容，也不是对发音、书写或长期保持能力的统一评分。

## 统计口径

三种数量分别计算，不相互替代：

1. **活动数**：实际保存的练习活动数。同一天再练一次，活动仍保留。
2. **不同内容数**：按 `type + id` 去重。例如同一个字的两次练习仍是一项内容。
3. **确认样本数**：新格式中来源为家长或程序、结果为三档之一的有效确认，按 `day + type + id + skill` 去重。

同一天同项同能力有多次有效确认时，只取按 `at` 时间排序的第一次；缺失时间的历史数据采用稳定的日初顺序。第一次需要再练、后来通过练习完成，不会把第一次覆盖成独立成功。活动历史没有删除，去重只影响统计与间隔推进。

能力单独保存。例如同一个汉字的“认字”和“书写”使用不同的 `skill`，即使以后都提供检查，也不会因为能认就算会写。

当前能力标识为：

| `skill` | 展示 |
| --- | --- |
| `poem-recitation` | 背诵 |
| `english-listening` | 听音辨认 |
| `hanzi-writing` | 书写 |
| `pinyin-reading` | 拼音认读 |
| `math-solving` | 解题 |

`english-speaking` 和 `hanzi-recognition` 预留标签，但不能因为有标签就视为已经提供了可靠检查。

跨天保持证据要求：已有该内容同能力的较早活动，本次是当天首次有效确认，与上次记录不是同一天，且本次没有 `afterPractice`、`observedExposure` 或 `exposureFirst` 标记。同日先练习再确认也不计为延迟检查。只有满足上述条件的独立成功，才用于“最长间隔若干天仍独立完成”和跨天独立完成日期数。第一次检查成功可以记录本次表现，但不能凭空产生保持天数。

旧活动只有日期、内容 ID 和类型时，最多显示“已练习”。旧英语活动即便带有 `listening: independent/supported`，也不自动转换成新统一确认样本；可保留原始历史说明。新活动保存标题快照，删除课堂内容后仍可知道当时练过什么。对没有快照的旧记录，使用现有内容标题，缺失时保留 ID，不猜测名称。

## 保存结构与失败重试

新活动保存在原有 `activity` 集合中，使用 `schemaVersion: 2`，无需迁移 SQLite 表。例如：

```json
{
  "schemaVersion": 2,
  "id": "write-木",
  "type": "write",
  "title": "汉字·木",
  "skill": "hanzi-writing",
  "result": "supported",
  "source": "parent",
  "day": "2026-10-02",
  "at": "2026-10-02T04:00:00.000Z",
  "details": {
    "method": "paper",
    "afterPractice": true
  }
}
```

`day` 是应用的本地学习日期，`at` 是完整时间戳。`details` 可保存本次题数、正确题数、提示、接触示范、描写或纸写等必要信息。`source: practice` 只代表练习参与，不能产生确认样本。

活动记录和相应内容进度通过同一个原子 PATCH 提交到服务端 SQLite。只有服务端成功确认保存，前端才完成该项练习；保存失败时，留在原页面重试会保留本次尝试及固定活动 ID，复用相同操作，避免重复新增和重复推进。退出后清空页面尝试，新一轮不会借用上一轮的缓存；已经发出的旧请求仍可能保存成功，但不会操作新页面。离开尚未提交的学习步骤不会自动伪造一个结果。删除课堂内容只影响内容安排，已经保存的活动历史保留。

删除课程时，服务端为尚无标题的旧活动补存当时的课程标题，不补写评价或熟练度。进度 JSON 的受控上限提高到 **5 MiB**，请求另留 64 KiB 的外层 JSON 余量；PATCH 合并后的总量与旧 PUT 的完整载荷都检查上限，超限会整批拒绝，不覆盖已有历史。

对带新格式确认的 PATCH，服务端在同一个 SQLite 写事务中核对最新历史并计算排期，防止另一台设备拿旧快照把同日的间隔拉长。同内容同能力按事件时间取首次确认；更早发生的结果晚到时，使用该日开始时的阶段修正。重试、提前练习和不同能力的后续确认不能覆盖已经确定的当天排期。旧客户端的请求格式继续兼容。

## 复习排期与兼容

仍使用 `1、2、4、7、15、30` 天的固定间隔：到期后独立完成逐步延长，需要提示或还要练习则回到短间隔。先听示范或练习后得到的结果不能用来证明延迟独立回忆，排期继续采用较短间隔。提前练习、同日重复确认不会连续拉长间隔。

完成确认的具体汉字和拼音才加入相应内容的复习，不一次性把整套字库、音表都加入每日任务。旧的 `pinyin-basic` 和 `write-basic` 整组任务在首次通过新流程完成后标记为不再安排，分别改为具体拼音、汉字 ID；旧的活动历史仍可查看。原有古诗、英语和其他内容的已保存进度继续保留。

这里没有根据有限样本拟合儿童个人遗忘曲线，也不输出精确的记忆概率。后续若调整算法，可以使用新保存的事件和能力信息；本次界面展示始终以可核对的实际记录为依据。

## 验证

```bash
node --check public/learning-model.js
node --check public/learning-records.js
node scripts/test-learning-model.cjs
node scripts/test-learning-records.cjs
```

模型回归覆盖旧数据、跨学科和能力去重、同日错后再对、日期边界、跨天证据、练后确认、少样本和输入不变。记录页回归覆盖日期筛选、数据展示、历史空状态、返回与只读行为。原有前端与服务端回归测试继续保留在 CI。
