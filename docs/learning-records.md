# 统一反馈与练习记录

各学科使用统一的确认选项，全科练习历史集中到首页的「练习记录」，保留可核对的原始活动。学习先逐项保存草稿，完成整组后统一写入活动、排期和奖励，具体评价仍落实到每项内容；成长日历另行记录组、水滴、浇水和礼物。统计展示本次完成表现和已有的跨天证据，不把一次点读、描写或选择题结果换算成精确的“熟练度分数”。复习排期仍使用原有固定间隔，没有接入 FSRS。完整产品规则见 [小树成长系统设计](growth-system.md)。

## 一套确认选项

| 保存结果 | 页面选项 | 含义 |
| --- | --- | --- |
| `independent` | ✓ 自己完成 | 这次检查中没有依赖提示完成 |
| `supported` | ◐ 提示后完成 | 需要提示或帮助才能完成 |
| `again` | ↻ 还要练习 | 当前还需要继续练习 |
| `practice` | 已练习 | 兼容已有的参与记录，没有有效确认；新界面的自由浏览不新增此类记录 |

需要人工观察时，三个选项的顺序、文字和样式一致。程序能够判断的题目直接记录结果，不再多加一组让家长重复评分的按钮。

| 内容 | 确认对象 | 确认来源 | 统计边界 |
| --- | --- | --- | --- |
| 古诗 | 背诵 | 家长确认 `parent` | 到期复习先隐藏正文；查看正文或听过范读，会记录本次接触示范；这次表现不算延迟独立回忆 |
| 英语 | 听音辨认 | 程序判断 `automatic` | 保留首次选图、提示和示范信息；跟说只记录参与，不认定发音正确 |
| 汉字 | 屏幕逐笔书写 | 程序判断 `automatic` | 按标准笔顺检查每笔方向、位置与形状，全部通过才完成；轮廓、提示、重试与先练习均记为 supported，不推断纸笔或认字能力；保留历史 parent 记录 |
| 拼音 | 拼音认读 | 家长确认 `parent` | 按具体音保存；读过或听过本身不等于独立认读 |
| 数学、分解组合 | 解题 | 程序判断 `automatic` | 依据本组每题的首次作答；保留题目签名、知识点、正误和各题首次保存时间 |

每组上限为古诗 5 首、数学或分解组合 10 题、拼音 10 个、汉字 5 个、英语 5 个。单项完成或数学逐题首次作答后保存草稿；完成本组实际计划后一次入账。古诗、拼音、汉字、英语按不同内容组成组；数学按实际题数汇总一个解题活动，并保存逐题结果供知识点排期使用。三档结果均可完成该项，不要求全部正确。

各学科「开始学习」与首页共用到期优先规则，按逾期、到期日排序，并排除当天已完成内容；有未完成草稿时先恢复。首页只复习，学科页在有余量时每组最多加入拼音 4 项、汉字 2 项、英语 2 项新内容。古诗默认课堂已学，只按日期复习，移除 `learned` 字段及已学筛选；旧写入也不会重新加入古诗 `learned`。上限不是必须凑满的数量，只有一项也能开始，不提前加入未到期内容；没有安排时提示休息。自由听、看、读、描不新增活动、不改排期、不发水，也不抵扣组进度。

每项 `phase` 决定先复习还是先学习，不能只看整组 `mode`：混合学习组中的到期汉字、拼音仍先独立检查。查看示范或练习后的确认带 `afterPractice` 标记，本次“自己完成”仍可显示，但与隔天未经示范的独立回忆分开。英语到期词首次听音选图正确即可结束该项，首次错误后进入练习，后续成功不覆盖首次结果。同日恢复草稿时仅对尚未完成的当前项保守标记接触示范，后续项不受影响；跨日恢复不自动添加提示标记，本次实际接触示范仍如实记录。程序无法观测线下是否额外练习，跨天间隔只描述已记录活动之间的距离。

汉字不再展示人工评分按钮：抬笔即校验，错误笔画重试，全部通过才自动保存。无提示、无轮廓、无重试且没有先练习时为 `independent`，其余完成为 `supported`。服务器检查笔画数完整性及结果与帮助标记的一致性；坐标轨迹仅在当前页面内存中处理，保存摘要，不上传原始轨迹。尚未写完的字不会变成完成记录。没有本地字形的自定义字保留在字库与历史中，但不排进自动学习计划；旧计划仅移除尚未完成且无字形的条目，已完成项目及其时间保留。

## 一个全科记录入口

首页的「练习记录」是统一入口，英语的每个词条不再各放记录按钮。记录页只读，不会创建活动，也不会更改下次复习日期。

- 日期可选今天、昨天、近 7 天或指定的历史日期。
- 每天再按古诗、英语、汉字、拼音、数学、分解组合汇总，直接列出练过的内容。英语同一天的词汇一起展示。
- 展示所选范围的学习天数、不同内容数、独立完成次数与有效确认次数。
- 七天趋势展示截至所选日期的连续七天，每天练过多少项不同内容。切换单日记录不会把之前六天清零。
- 各学科分别展示确认结果，注明程序判断或家长确认。不同能力不混成一个“会了”的标签。
- 历史较少或没有新格式确认时显示“暂无确认”，不推算百分比分数。空日期正常显示没有记录。

“独立 4 / 5 次”是五次有效确认中四次独立完成。它没有承诺孩子现在能记住 80% 的内容，也不是对发音、书写或长期保持能力的统一评分。

## 统计口径

三种数量分别计算，不相互替代：

1. **活动数**：实际保存的练习活动数。同一天另一个完整组中的重复内容仍保留活动；自由浏览和尚未完成的草稿没有活动；草稿完成后再按各项原始日期入账。
2. **不同内容数**：按 `type + id` 去重。例如同一个字的两次练习仍是一项内容。
3. **确认样本数**：新格式中来源为家长或程序、结果为三档之一的有效确认，按 `day + type + id + skill` 去重。

同一天同项同能力有多次有效确认时，只取按 `at` 时间排序的第一次；缺失时间的历史数据采用稳定的日初顺序。第一次需要再练、后来通过练习完成，不会把第一次覆盖成独立成功。活动历史没有删除，去重只影响统计与间隔推进。

能力单独保存。例如同一个汉字的“认字”和“书写”使用不同的 `skill`，即使以后都提供检查，也不会因为能认就算会写。

当前能力标识为：

| `skill` | 展示 |
| --- | --- |
| `poem-recitation` | 背诵 |
| `english-listening` | 听音辨认 |
| `hanzi-writing` | 书写 |
| `pinyin-reading` | 拼音认读 |
| `math-solving` | 解题 |

`english-speaking` 和 `hanzi-recognition` 预留标签，但不能因为有标签就视为已经提供了可靠检查。

跨天保持证据要求：已有该内容同能力的较早活动，本次是当天首次有效确认，与上次记录不是同一天，且本次没有 `afterPractice`、`observedExposure` 或 `exposureFirst` 标记。同日先练习再确认也不计为延迟检查。只有满足上述条件的独立成功，才用于“最长间隔若干天仍独立完成”和跨天独立完成日期数。第一次检查成功可以记录本次表现，但不能凭空产生保持天数。

旧活动只有日期、内容 ID 和类型时，最多显示“已练习”。旧英语活动即便带有 `listening: independent/supported`，也不自动转换成新统一确认样本；可保留原始历史说明。新活动保存标题快照，删除课堂内容后仍可知道当时练过什么。对没有快照的旧记录，使用现有内容标题，缺失时保留 ID，不猜测名称。

## 保存结构与失败重试

新活动保存在原有 `activity` 集合中，使用 `schemaVersion: 2`，无需迁移 SQLite 表。例如：

```json
{
  "schemaVersion": 2,
  "id": "write-char-6728",
  "type": "write",
  "title": "汉字·木",
  "skill": "hanzi-writing",
  "result": "supported",
  "source": "automatic",
  "day": "2026-10-02",
  "at": "2026-10-02T04:00:00.000Z",
  "details": {
    "method": "stroke-quiz",
    "engine": "hanzi-writer-3.7.3",
    "character": "木",
    "totalStrokes": 4,
    "completedStrokes": 4,
    "totalMistakes": 1,
    "hintsUsed": 1,
    "outlineShown": true,
    "assisted": true,
    "afterPractice": true
  }
}
```

新组内各项的 `day`、`at` 由服务器在首次保存该项草稿时生成，日期按北京时间计算。整组完成保留已保存的原时间，跨天继续不把旧答案计成新的当天检查；客户端提供的日期或时间不作为入账依据。数学逐题首次结果同样保留各自时间，汇总活动使用其确认时间；水滴与完整组日期独立采用本组完成日。无草稿的旧客户端完整组继续使用服务端完成时间。历史活动保持原有日期。`details` 可保存本次题数、首次正确题数、题目签名、提示、接触示范、描写或纸写等必要信息。已有 `source: practice` 只代表参与，不能产生确认样本。

草稿通过 `POST /api/study-sessions` 提交 `{ id, type, mode, items, entries, progress }`，保存在 `payload.studySessions[id]`。`items` 固定原内容与顺序，每项带 `phase: learn/review`；`entries` 是已完成前缀，`progress.practice` 保存数学题目和逐题结果。每学科最多一个活动草稿，已有计划、首次答案不能改写或缩短，重复提交保留首次服务端时间。显式 `DELETE /api/study-sessions?id=...` 可放弃草稿。

整组通过 `POST /api/study-groups` 提交 `{ id, type, mode, entries }`。`mode` 为 `learn` 或 `review`，`entries` 含每项的 `id`、`type`、`title`、`skill`、`result`、`source` 和 `details`；活动统一归一为 `schemaVersion: 2`。数学、分解组合只提交一个汇总条目，`details.total` 为本组实际题数，`correct` 为首次正确题数，`questionKeys` 和 `questionResults` 与题数、顺序一致；逐题结果带 `key`、`knowledgeId`、`correct`。其他学科接受 1 项至组量上限，内容 ID 不重复。有草稿时完整提交必须与原计划和已保存前缀一致。

草稿保存成功后才继续下一项，失败保留原首次结果供重试；退出、切换学科、刷新、关闭或换设备后按服务端前缀继续。草稿不产生正式活动、不改排期、不发水。完成整组时，活动、排期、完整组记录、奖励和草稿删除在同一个 SQLite 事务中提交。保存期间防止重复操作，使用固定组 ID 和同一批结果重试；已答完但整组尚未入账的草稿可恢复后直接提交。只有服务端确认成功才显示到账；已成功但响应丢失时，重试不会再次新增活动、改变首次回答或发水，跨日重试仍保持原完成日。整组完成后返回首页，不自动进入下一组。

草稿按每项 `phase` 验证复习资格，古诗无需 `learned`，其他复习项仍须已有学习记录；完整组要求内容仍可用，其中一项已被其他设备删除时，整组返回冲突，不部分保存，也不擅自恢复课程。删除课堂内容只影响后续安排，已经保存的活动历史保留。当前界面已移除家长内容管理；原有 PATCH 接口仅为已有客户端兼容保留。

删除课程时，服务端为尚无标题的旧活动补存当时的课程标题，不补写评价或熟练度。服务端进度 JSON 的持久化上限为 **32 MiB**，课程初始化、PATCH、整组保存和浇水合并后的总量都检查上限，超限会整批拒绝，不覆盖已有历史。单次请求仍限制在 **5 MiB + 64 KiB**，旧 PUT 的输入载荷仍限制在 5 MiB；请求体限制与累计存储限制分别检查，因此历史超过 5 MiB 后仍能通过小请求管理内容、保存完整组和浇水。按每天三组各十个拼音、三次浇水的结构模拟，365 天约占 3.76 MiB；32 MiB 是约八年量级的容量余量，额外练习和既有历史会影响实际可用时长，不承诺无限保存。

整组 API 沿用服务端的新格式确认排期核对：在 SQLite 写事务中读取最新历史，防止另一台设备拿旧快照把同日间隔拉长。每项内容按自己的结果计算，不把整组当作同一个掌握等级。提前温习保留原定日期，并带 `afterPractice` 标记。旧格式 PATCH 继续兼容，其中同内容同能力按事件时间取首次确认；更早发生的结果晚到时，使用该日开始时的阶段修正。重试、提前练习和不同能力的后续确认不会连续拉长间隔。

## 成长账本与日历

每个完整组可获得 1 滴水，全学科合计每天最多 3 滴。服务端按北京时间核对同日内容组合，组合内顺序改变或从另一入口重复完成都不重复发水；数学使用排序后的 `questionKeys` 计算组合签名。达到上限后，完整组仍保存活动和组记录，`waterAwarded` 为 0，不产生次日补领额度。

`POST /api/garden/water` 只接受固定操作 ID：`{ id }`。当天至少有一个成功组、水壶余额大于零、当天浇水不足 3 次时，才能消耗 1 滴水。水滴余额由历次组奖励总和减去实际浇水次数计算，不接受客户端余额。存水不过期，但休息日不会因查看页面而自动浇水或成长。

实际累计浇水每达到 12 的倍数，生成一个成长里程碑和礼物；扣水、累计次数与礼物在同一个事务中保存。操作 ID 保证重复点击或响应丢失后的重试只算一次。礼物不指定实物、不提供线下已发放状态，重复查看不会再次发奖。成年树按固定阶段继续变化，每次仍需 12 滴，保留余量。

成长数据位于 `payload.garden`：

| 字段 | 内容 |
| --- | --- |
| `version`、`startedAt` | 账本版本 1 与首次启用时间 |
| `groups[id]` | `id`、`type`、`mode`、`day`、`at`、`count`、`contentIds`、`waterAwarded`、`signature` |
| `watering[id]` | `id`、`day`、`at`、累计 `total`、本次 `milestone`（无新里程碑时为 0） |
| `gifts[序号]` | `milestone`、`day`、`at`、对应累计 `waterTotal` |

两个 POST 成功时均返回 `{ ok: true, payload, updatedAt }`。账本按需初始化，旧活动不补发水滴或礼物。PATCH 的集合白名单不包含 `garden` 或 `studySessions`。尚无完整组及草稿时保留旧 PUT 兼容，且不能注入账本或草稿；一旦 `garden.groups` 或 `studySessions` 非空，旧 PUT 若时间戳足以覆盖当前状态，返回 `409 legacy_client_upgrade_required`，同时返回当前 `payload`、`updatedAt` 和升级提示，防止成长账本或未完成计划与相关活动、排期分离。过期 PUT 不发生写入，仍可返回当前服务端快照。

首页「成长日历」和「练习记录」分别服务于成长与学习表现。日历默认本月，可切换历史月份；日期格显示获得水滴与礼物，日期详情分别列出完整组、获得水滴、浇水次数及礼物，月汇总也分别计算这四项。自由浏览和退出半组不进入日历，休息日留空，未来日期不预测礼物。记录页继续按内容与能力核对真实结果。

## 复习排期与兼容

仍使用 `1、2、4、7、15、30` 天作为初始工程规则，不声称这是对所有儿童、所有内容都最优的科学间隔：到期后独立完成逐步延长，需要提示或还要练习则回到短间隔。先听示范或练习后得到的结果不能用来证明延迟独立回忆，排期继续采用较短间隔。提前练习、同日重复确认不会连续拉长间隔。

只有所在完整学习组成功保存后，新确认的具体汉字和拼音才加入相应内容的复习，不一次性把整套字库、音表都加入每日任务。旧的 `pinyin-basic` 和 `write-basic` 整科任务在首次对应完整新组成功保存后标记为不再安排，分别改为具体拼音、汉字 ID；旧的活动历史仍可查看。原有古诗、英语和其他内容的已保存进度继续保留。

数学在 `items[题型ID].mathKnowledge[知识点ID]` 保存各知识点的阶段、下次复习日、首次检查日、错误数和最近结果。加法按总数、减法按被减数、分解组合按总数与求整体/部分区分知识点；组内优先覆盖到期点，再给易错点提供不同题面，尽量避开最近两组原题。每题第一次答案固定，同日同知识点不连续推进间隔；未到期内容不用于凑题，剩余题数不足上限时可以结束短组。

这里没有根据有限样本拟合儿童个人遗忘曲线，也不输出精确的记忆概率。后续若调整算法，可以使用新保存的事件和能力信息；本次界面展示始终以可核对的实际记录为依据。
