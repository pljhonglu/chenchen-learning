# 辰辰的学习乐园

给幼儿园大班、约 5–6 岁孩子的课后记忆练习。内置 36 首古诗词，按课堂已学内容安排复习；各学科从内置内容中组成学习组。孩子用绘本插图、自然语音和分组练习复习古诗、数学、拼音、汉字与英语，完成整组获得水滴，照顾同一株植物，让小花园一点点长大。

服务端使用 **Go + SQLite**，前端为无需构建的 HTML/CSS/JavaScript。支持手机、平板和电脑；访问同一台服务器可以同步学习进度。

## 使用方式

1. 内置古诗默认已在课堂学过，直接按到期日期复习，不再使用“已学 / 未学”开关或 `learned` 字段判定古诗资格。升级保留已有的复习阶段、日期与活动，尚无记录的古诗从今天巩固开始。不再提供独立家长入口及课程新增、删除、恢复操作；已保存的自定义内容、隐藏状态和学习记录继续保留。
2. 「开始学习」和首页复习共用到期优先的选题规则：先排逾期、到期内容，跳过今天已完成的内容。古诗只复习；拼音、汉字、英语在有余量时分别最多加入 4、2、2 项新内容。非数学组只把 10 或 5 项作为上限，哪怕只有 1 项到期也能开始，不用未到期内容凑数；有未完成计划时优先继续上次进度。
3. 每首内置古诗有一张绘本插图。复习时先隐藏正文，请孩子尝试回忆；可随时查看原文或听示范，这次接触会计入提示证据。自由浏览仍显示完整诗文与拼音；返回诗卡列表时保留滚动位置、搜索词和筛选条件。数学加减法、分解组合每组最多 10 题，按到期知识点和易错知识点选题，变换具体算式并记录每题首次答案；答完即判断对错，保存进度后由孩子进入下一题；拼音和例字可直接点读，汉字可以对照田字格描写。单独打开内容自由听、看、读、描，不保存学习记录、不改变排期，也不发水滴。
4. 需要家长确认的地方统一使用「自己完成」「提示后完成」「还要练习」。汉字屏幕逐笔书写、英语听音选图与数学答题由程序判断；拼音认读和古诗背诵由家长确认。汉字全部笔画通过后自动保存，其余项目按实际三档结果完成。单项完成先保存草稿，整组结束再统一写入学习记录、排期和奖励，不把听过、描过或完成整组等同于掌握。
5. 首页「练习记录」统一查看所有学科，可切换今天、昨天、近 7 天或指定日期。按天汇总练过的内容，并展示不同内容数、学习天数、确认结果和七天趋势；英语词卡内不再分别放练习记录入口。
6. 新开始的内容当天先巩固；到期后独立完成，按 1、2、4、7、15、30 天间隔逐步安排。需要提示、还要练习，或先练习/听示范后才完成的内容，较早再检查；同一天重复评价不会连续跳级。本次仍采用原有固定间隔规则，未引入 FSRS 或个体化遗忘概率模型。

课堂内容、复习进度、未完成计划和成长账本只保存在服务端 SQLite，不写入浏览器本地存储。每项完成、数学每题首次作答后都先保存草稿；退出、换设备、刷新或跨天后可继续原计划和已确认结果。尚未完成的当前内容可能需要重新检查；同日恢复时保守记录为练后确认，跨日恢复不自动视作已看过提示。草稿不发水、不提前推进排期；整组保存成功后才统一入账，沿用各项首次保存的服务端时间，水滴按整组完成日计算。保存失败保留相同结果供重试，固定请求 ID 防止重复入账。完成后返回首页，不自动开始下一组。

「独立 4 / 5 次」表示所选日期内有效确认的结果，不是“熟练度 80%”。同日同内容同能力只取首次有效确认，同日完成其他完整组中的重复内容仍保留活动记录；练后确认与跨天保持证据分别处理。旧记录只能说明曾练习，不补造过去的熟练度。字段、统计口径与保存行为见 [统一反馈和练习记录说明](docs/learning-records.md)。

36 首内置古诗词使用预生成的普通话自然语音 MP3（AI 合成，并非真人录制），随应用分发，不再由设备系统临时读诗。详情页只有一个朗读按钮：点击播放，再点暂停，再点从原位置继续，离开页面自动停止；特定多音字在生成输入中做校正，页面保持原诗文字。播放时无需语音服务密钥或外部 TTS 连接；音频不可用时提示重试，不自动切回系统读诗。以前保存的自定义古诗暂未配音，由家长陪读；普通操作提示仍使用设备语音。详见 [音频说明](docs/poem-audio.md)。

新增苏轼《水调歌头·明月几时有》完整词文（“但愿人长久，千里共婵娟”），配有逐字拼音、自然朗读和中秋赏月插图。

插图使用内置 imagegen 逐首生成，重点保留诗中的人物、动物或景物，避免复杂场面。文件位于 `public/images/poems/`；[插图提示词](docs/poem-image-prompts.md)记录每首场景。

## 小树成长与水滴

| 学科 | 每组上限 | 完整组奖励 |
| --- | --- | --- |
| 古诗 | 最多 5 首不同古诗 | 1 滴水 |
| 数学 | 最多 10 题，按加减法或分解组合题型 | 1 滴水 |
| 拼音 | 最多 10 个不同拼音 | 1 滴水 |
| 汉字 | 最多 5 个不同汉字 | 1 滴水 |
| 英语 | 最多 5 个不同词汇 | 1 滴水 |

全学科每天合计最多获得 **3 滴水**。当天至少成功保存一组后开放浇水，可使用以前的存水；每次浇水消耗 1 滴，每天最多 **3 次**。两项限额由服务器统一按北京时间计算。水滴不过期，不要求连续签到，休息时树不倒退；每天 3 次是上限，不是必须完成的任务。

同一个组重试不重复记录或发水，同日相同内容组合调换顺序也不重复发水。达到奖励上限后，完整组仍保存学习记录，但不产生次日补领奖励。达到浇水上限后，按钮停用并提示「小树今天喝好啦」。

实际累计浇下的水每达到 **12 的倍数**，小树发生一次成长变化，并出现一个 🎁 礼物盒；余量保留。成年后仍在同一棵树上按「长嫩叶、花苞、开花、结果」循环，每步仍需 12 滴。礼物只展示盒子、序号、日期和对应变化，不显示具体奖品、不承诺实物，也不记录线下是否已送出。从零开始每天浇 3 滴约需 4 个学习日，每天浇 1 滴约需 12 个学习日，不承诺固定日期领奖。

首页「成长日历」按月查看完成组、获得水滴、实际浇水和礼物，分别统计收入与消耗；休息日留空，未来日期不预测礼物。原有「练习记录」继续查看各内容的具体表现。成长从新系统启用后的完整组开始，不为旧活动补发水滴或礼物。完整规则见 [小树成长系统设计](docs/growth-system.md)。

成长场景采用生成的绘本环境图片、SVG 植物与本地 GSAP 3.15.0 时间线。远山、草地、花丛来自水彩背景，透明云朵图片缓慢漂移；树干逐渐分叉形成层叠树冠，叶片从连接点展开，花瓣依次打开，青果逐渐变色，水滴直接落到树根。闲置时有轻微风摆、蝴蝶扇翅与小鸟眨眼，离屏、后台或开启减少动态效果时暂停。普通照顾约 1.9 秒，成长约 2.75 秒，礼物在生长结束后出现；当天第 3 次也完整播放后再休息。减少动态效果或动画库不可用时直接显示保存后的阶段，切页或转入后台时清理播放。实现与验收说明见 [混合绘本小花园](docs/garden-svg-scene.md)，生成素材与完整提示词见 [当前素材说明](docs/garden-painted-assets.md)，此前素材保留在[历史素材说明](docs/garden-image-prompts.md)。

使用 `node scripts/preview-garden.cjs` 可在 `http://127.0.0.1:8766` 预览花园。页面不显示调试工具栏；开发时可在控制台使用 `previewGarden(累计浇水数, 今日浇水数)` 查看全部 16 阶段、成长前一滴和每日第 3 次浇水。该工具只使用内存模拟数据，无需 Go 后端，不写真实学习记录。浏览器回归可在此页面执行 `agent-browser eval --stdin < scripts/test-garden-scene.browser.js`。预览端口可用 `PORT` 指定。

## 英语小花园

首页「今日复习」里的英语组按复习日期安排；底部「玩英语」打开统一词卡列表，点击「开始学习」组成最多 5 个词的学习组。全部 87 张词卡放在一起，可按主题筛选，单独点击后进入词句自由浏览页，返回时保留筛选和浏览位置。程序提供英文单词、完整句子和中文解释点读，家长无需示范发音。

- 内容包括 **39 项课堂词汇 + 48 项生活拓展**，每项都有经过逐句整理的范句和中文含义。`pencil case` 按一个词汇项计，`pear` 暂按水果语境整理；`beans` 的课堂译义仍标注待核对。
- 英语每组 1–5 个不同词，先排到期词；学科页在有余量时最多加入 2 个尚未练过的课堂词，首页复习不加入新词，也不提前补齐未到期词。完成的词会保存，可以随时休息后继续。词卡可自由点读，不占用组进度，也不产生记录。
- 到期词先听音选图，首次选对即可完成该词复习；首次选错则保留原结果，继续示范和练习。新课堂词先听音选图，再听词跟说、听句子、看图尝试；第一次接触生活拓展时先听示范，再选图。生活拓展不会自动全部加入任务，只有该词所在完整学习组成功保存后，才纳入具体词汇的间隔复习。
- 听音必须成功播放后才能作答。首次选对、提示后找到以及新词跟学分开记录；不会因为最终选对就把错误的首次回答覆盖成独立完成。
- 开口可以选择「我试着说了」或「今天先听听」。**没有麦克风采集、语音识别或发音评分**，参与记录不代表发音准确，家长也无需判音。
- 复用服务端 SQLite，每完成一个词保存草稿，整组结束再统一提交各词真实结果、排期及本组奖励。保存失败可重试，同一组使用固定 ID，避免重复计数。同日重复或提前练习不会连续拉长复习间隔。
- 家长从首页统一的「练习记录」查看已成功保存组中的英语词汇及听音辨认结果；同一天的词汇汇总在一起，不需要逐词打开记录。开口参与仍保留在活动数据中，不作为会说或发音正确的依据。以前暂停的英语内容仍保持原状态，原有活动历史保留。

全部 **276 段 MP3** 随应用分发：每个词的单词、句子、中文解释，以及 15 段中文引导。英文使用英式 Sonia，中文使用晓晓，均为 AI 合成音频；部署后不连接外部 TTS，不会回退成设备中文声音读英语。支持暂停、继续、重播、失败重试和切换页面停止。详见 [英语音频与重建说明](docs/english-audio.md)。

绘本图卡沿用暖色水彩、水粉和奶油纸纹。11 张图集提供 71 个具象词与情境，数字通过重复单个苹果准确计数，颜色用色块表示。WebP 图集总计约 1.82 MiB。生成提示词、原始来源与分格映射见 [英语插图说明](docs/english-image-prompts.md)。

这是一套家庭听说练习内容，不是幼升小必会词表。每天是否继续、是否增加拓展词，按孩子的状态决定。

## 汉字写一写

内置 **150 个生活常用字**。写汉字分为两页：第一页提供「开始学习」和完整字库，字库按真实笔画数从少到多排列；点字后进入第二页的田字格自由读写页，点「全部汉字」可回到原来的列表位置。学习组与首页复习组最多包含 5 个不同汉字，按本组顺序继续，整组完成后返回首页。以前保存的自定义汉字仍出现在同一列表，原有学习记录与课堂复习 ID 保留。选字依据与完整字表见 [书写准备调研](docs/writing-curriculum.md)。

- 每字显示带声调的拼音，点拼音即可听字音。每字配 3 个常用词或熟悉的短语，词语也带逐字拼音，直接点词语听范读。
- 每次抬笔使用本地 Hanzi Writer 3.7.3 对照标准轨迹检查笔顺、方向、位置和基本形状，通过后进入下一笔。支持「看笔顺」「提示这一笔」「重新写」，连续错误会提示当前笔画，错误次数再多也不会强制判对。
- 新字和自由练习显示浅色轮廓；有字音的到期复习先隐藏轮廓和词语，可听字音后自己写。查看词语、看示范、请求提示、重写及错误重试都会保留帮助信息。加载失败时提供重试，不能把未校验的描画当成完成。
- 全部笔画通过后自动保存当前字并进入下一项，汉字页无需家长确认。无轮廓、无提示、无错误且未先练习的结果记为「自己完成」，其余完成记为「提示后完成」。每字先保存进度，整组结束统一记录与排期。自由练习仍自动反馈，但不保存学习记录。屏幕笔画校验不代表纸笔书写、美观评分或认字能力；纸写确认入口已移除，历史记录保留。
- 150 字、450 个词语搭配使用 **553 段字词点读 MP3**（相同词共用录音），另有原来的笔顺序数音频。资源随应用分发，播放时无需外部服务。字音、词音、笔顺互相切换时会停止前一段声音，切字或离开页面同样停止。
- 150 字均有本地笔顺，另带「辰、明」供已有课堂和姓名示例使用；只有具备本地笔画数据的字会进入自动学习计划。旧草稿移除尚未完成且无数据的字，保留已完成项目与时间；无数据字仍保留在字库和历史中。未提供的拼音与词语不会自动猜测。

这份字库是兴趣选择材料，教育部相关指南没有统一的大班必写字表。字库中的字不会自动全部加入每日任务。

孩子也可只自由看、读、写一个字，按兴趣随时休息；只有完整组成功保存才记录学习和发水，未完成组保留已确认进度，回来可以继续。音频为 AI 合成普通话，详见 [写字音频说明](docs/writing-audio.md)。逐笔动画采用 [Hanzi Writer](public/vendor/README.md)，字形数据来源、独立许可和重建方式见 [笔顺数据说明](public/data/strokes/README.md)。

## 拼音小卡片

23 个声母、24 个韵母都能直接点读。点击大拼音或下方拼音卡片播放该音，声母采用教学呼读音；下方固定显示 3 个带声调拼音的例字，点汉字单独听字音，例如 `b` 下方是「爸 bà、包 bāo、白 bái」。家长无需示范。

拼音使用专用录音，例字使用预生成的普通话音频；全部随应用分发，不把拼音交给设备当字词或英文字母朗读。连续点读会停止上一段，切换页面也会停止；声音未加载成功可再点重试。点击「开始学习」自动组成最多 10 个不同拼音；到期项先独立认读，新项再听示范练习，每组最多加入 4 个新音。家长逐项选择三档结果，每项完成先保存草稿，整组完成后统一写入确认和复习排期。只听和单项自由浏览不记录；未完成组提前离开后可继续。旧的整科拼音任务在首次完整新组保存后退出排期，旧活动历史仍保留。素材来源、许可与重建说明见 [拼音音频说明](docs/pinyin-audio.md)。

## Docker 快速启动

GitHub Actions 构建 `linux/amd64` 和 `linux/arm64`，镜像为：

```text
ghcr.io/pljhonglu/chenchen-learning:latest
```

```bash
docker run -d --name chenchen-learning \
  -p 8080:8080 \
  -v chenchen-learning-data:/data \
  --restart unless-stopped \
  ghcr.io/pljhonglu/chenchen-learning:latest
```

浏览器打开 `http://服务器IP:8080/`，健康检查为 `/api/health`。

或从源码构建：

```bash
git clone https://github.com/pljhonglu/chenchen-learning.git
cd chenchen-learning
docker compose up -d --build
```

## 从 Python 版本升级

Go 版本沿用 `/data/progress.db`、`progress` 表和原有 API，原来的学习记录无需转换。升级前先停止旧容器并备份数据卷，替换镜像时挂载原来的 `chenchen-learning-data` 卷。不要运行 `docker compose down -v`，这个命令会删除数据卷。

使用上述 `docker run` 方式的部署可以这样更新：

```bash
docker pull ghcr.io/pljhonglu/chenchen-learning:latest
docker stop chenchen-learning
# 此时可备份 chenchen-learning-data 卷。
docker rm chenchen-learning
docker run -d --name chenchen-learning \
  -p 8080:8080 \
  -v chenchen-learning-data:/data \
  --restart unless-stopped \
  ghcr.io/pljhonglu/chenchen-learning:latest
```

镜像以 UID/GID `10001` 运行。使用 NAS 主机目录绑定 `/data` 时，该目录需要允许 UID `10001` 读写；原先已可用的数据目录可继续使用。复制数据库备份时应先停止容器，避免遗漏未写回数据库的事务。

## API 与持久化

- `GET /api/health`：服务健康状态。
- `GET /api/progress`：`{ found, payload, updatedAt }`。
- `PUT /api/progress`：请求 `{ payload: { items: {} }, clientUpdatedAt }`；返回 `{ ok, merged, kept, payload, updatedAt }`。
- 首次完整组保存前，`PUT` 为旧客户端保留按时间戳保存的兼容行为，且不能注入成长账本。已有 `garden.groups` 或未完成的 `studySessions` 后，准备覆盖当前状态的旧 `PUT` 返回 `409 legacy_client_upgrade_required`，附当前 `payload`、`updatedAt` 和升级提示，防止活动、排期与成长账本分离；过期快照仍只返回服务端现有状态。
- `PATCH /api/progress`：为已有客户端保留的内容原子更新接口；当前界面已移除课堂内容管理，不再从页面发起课程增删；请求 `{ operations: [{ op, collection, key, value }] }`，返回 `{ ok, payload, updatedAt }`。`op` 为 `create`、`set`、`merge` 或 `delete`；集合为 `items`、`customPoems`、`customCharacters`、`activity`、`hiddenCourses`，不允许操作 `garden`。
- `POST /api/study-sessions`：请求 `{ id, type, mode, items, entries, progress }`，保存原计划、逐项完成前缀及数学逐题进度。每学科保留一个未完成计划，计划与已有首次结果不可改写；服务端为新结果记首次保存时间。`DELETE /api/study-sessions?id=...` 可显式放弃草稿，不影响已完成活动。
- `POST /api/study-groups`：请求 `{ id, type, mode, entries }`，`mode` 为 `learn` 或 `review`。服务端验证计划及组量上限，一次保存逐项活动、各项复习排期和组奖励，并移除对应草稿。数学与分解组合提交一个汇总条目，`details` 包含 实际题数 `total`（最多 10）、首次答对数 `correct`、对应的 `questionKeys` 和 `questionResults`；后者包含 `knowledgeId` 与首次正误，用于各知识点单独排期。其他学科提交 1 至上限数量的具体内容条目。
- `POST /api/garden/water`：请求 `{ id }`。服务端验证今日已完成组、余额及每日浇水限额，一次保存扣水、累计成长与 12 滴倍数的礼物。这些 POST 均返回 `{ ok, payload, updatedAt }`，使用固定请求 ID 重试；单项与逐题日期保留首次草稿保存的服务端时间，奖励日期取整组完成日；跨日重试不会再次记账。
- `payload.garden` 包含 `version`、`startedAt` 和以 ID 为键的 `groups`、`watering`、`gifts`。余额由已发水的完整组减去实际浇水次数计算，不信任客户端余额。新接口按需初始化账本，不从旧活动追补奖励。
- 每个 PATCH 在 SQLite 事务中整体应用，服务端生成更新时间。`merge` 只允许更新仍存在的条目，已被其他设备删除时返回 409，避免旧页面把课程重新保存回来。
- 新格式确认的排期在服务端核对当天首次有效记录，避免不同设备的旧快照重复推进；提前练习保持原日期。删除课堂内容保留既有练习历史，缺失的旧标题在删除时补存快照。
- 服务端完整进度的持久化上限为 **32 MiB**，课程初始化、PATCH、整组保存和浇水合并后都校验，超限整批拒绝并保留已有记录。单次 HTTP 请求仍限制在 **5 MiB + 64 KiB** 包装余量内，旧 PUT 的输入载荷仍不超过 5 MiB；累积历史超过 5 MiB 后，小请求的兼容内容更新与学习、浇水仍可正常保存。以每天三组各十个拼音、三次浇水估算，32 MiB 提供约八年的记录容量；实际容量取决于既有历史、内容和额外练习次数，并非无限存储。
- 兼容接口的课程新增使用 `create`：已有记录保持原样，避免另一台设备重复添加时覆盖复习进度。`set` 用于写入完整内容或带固定 ID 的练习活动，`delete` 不带 `value`。
- `/data/progress.db` 是唯一持久化来源；原来已上传服务器的记录可以直接继续使用，旧浏览器缓存不再读取。

这是家庭使用的共享进度服务，没有账户隔离。建议用于家庭局域网；需要远程访问时，使用带登录的反向代理或家庭 VPN。

## 构建验证

每次 main 提交和 PR 都检查 Go 服务端、浏览器脚本和同步/复习/语音回归测试；Docker 镜像发布前，会启动临时容器验证健康接口、静态课程文件和重启后的 SQLite 持久化。`main` 更新后自动发布 `latest`，同时发布对应提交的 `sha-*` 标签。

```bash
docker build -t chenchen-learning:test .
bash scripts/smoke-container.sh chenchen-learning:test
```
